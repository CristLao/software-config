# 冲突规则的处理

| 原始做法 | 采用的规则及原因 |
| --- | --- |
| Cursor 用直引号, Vercel 用弯引号; Vercel 禁止源码硬换行和分隔线 | 用户和项目规范优先. 当前仓库使用英文标点, 普通文本按逻辑换行并保留 Markdown 行尾双空格, 可以按需使用分隔线 |
| 禁用所有破折号, 严格限定冒号位置 | 减少用标点掩盖句子结构的问题. 代码, 引文和有意义的原始格式保持准确 |
| 英文句子少于 20 词, 段落 2 到 4 句, 示例最多 25 行和 80 列 | 以一次读懂和完成操作判断长度, 不把英文阈值当作中文硬限制, 不随意拆散连续命令 |
| 每页和每个大节必须有摘要, 所有页面必须有内容计划和元数据 | 长文按需交代用途, 短文直接进入内容. 不生成重复摘要或项目不支持的元数据 |
| 用具体数字替换所有模糊量词 | 只有证据支持时才量化. 无数据则去掉夸大修饰或说明不确定性, 保留必要限定 |
| 所有被动句和通用词都视为问题 | 优先明确动作和主体. 主体不重要时可用被动句, 必要术语不机械替换 |
| GitHub 要求每次追问并等待大纲审批, 限制外部资料来源 | 从请求和上下文判断, 只问阻碍任务的问题. 遵循用户对资料和操作的授权, 不添加固定审批 |
| Vercel 固定用 TypeScript, Steps 组件, 特定模型名, 站点链接和演示账户 | 沿用目标项目的语言, 版本和组件, 核对实际界面与官方资料, 不硬编码厂商约定 |
| 上游命令的调用开关, PR 审批, 联系团队和企业模型规定 | 不作为通用写作要求. 本 skill 保持默认可发现, 不附加外部操作或组织流程 |
| 极度精简审查输出, 允许牺牲语法 | 简洁但写完整意思. 给问题位置与改法, 不让读者解码缩写和碎片 |

检查信号用于找出无信息量的表达, 不承诺推断作者身份或绕过 AI 检测.  
需要保留的事实, 限制和作者声音, 优先于表面上的风格统一.
