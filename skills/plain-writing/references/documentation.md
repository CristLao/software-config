<h1><center>文档写作与审校</center></h1>

# 先判断文档的用途

根据读者此刻的目标选择组织方式. 这些分类用于决定内容取舍, 不要求写入元数据.  
读者, 目标和范围能从上下文确定时直接写; 长文先拟内部提纲即可, 用户要求讨论方案时再展示.

| 类型 | 读者的目标 | 组织方式与语气 |
| --- | --- | --- |
| 教程 Tutorial | 第一次学会并完成一件事 | 给明确起点, 前提, 连续练习和可验证结果. 语气耐心, 不突然引入未准备的条件 |
| 操作指南 How-to | 解决手头的具体问题 | 直接列前提, 操作和结果. 以完成任务为主, 原理链接到别处 |
| 参考 Reference | 查找准确的信息 | 按 API, 参数, 配置项或功能对象组织. 覆盖取值, 默认值, 返回值, 错误与限制 |
| 原理说明 Explanation | 理解原因和取舍 | 围绕问题解释概念, 机制, 背景和权衡. 用适量例子或类比帮助理解 |
| 故障排查 Troubleshooting | 判断故障并恢复 | 从症状和错误信息进入, 对应可能原因, 检查方法, 修复和验证. 承认具体影响后直接帮助解决 |
| 入口页 Landing | 找到适合自己的下一步 | 简述适用对象和用途, 提供清楚的路径, 不堆功能口号 |

以一个主要目标组织一页. 同时需要教学, 操作和参考时, 控制各部分边界, 必要时拆页互链.  
面向不同读者时先写共同需要的短说明, 再按任务或经验分节. 不为完整而给局部修订扩写整套文档.

# 写到读者能够操作

- 标题围绕读者任务, 如 "配置环境变量", 少用只有内部功能名的标题.
- 开头在需要时交代适用对象, 用途和完成后的结果. 大章节的首句帮助读者进入主题, 不机械增加每节摘要.
- 在操作前说明真正需要的环境, 权限, 依赖和初始状态. 不把可选项写成必备条件.
- 给出实际入口, 命令或配置位置, 不写无法执行的 "完成相关配置". 标明步骤是在哪个环境执行.
- 按依赖顺序操作, 在关键步骤给预期输出或可观察结果. 出错时提供与当前任务相关的检查入口.
- 原因, 例外和限制放到影响判断的位置. 非主路径的补充用短注释或链接处理, 避免打断步骤.
- 术语和缩写在首次需要时解释. 参考文档按对象方便查找, 教学内容按读者任务推进.
- 保持名称, 路径写法, 时态, 单位和语气一致. 已有项目约定优先, 不自行更改界面文字.
- 说明计费时交代计量单位, 触发计费的条件, 包含项和超额规则. 有价格对比时用表格, 数值必须可核实.

# 让示例准确且足够

- 示例语言和工具沿用目标项目, 不默认改成 TypeScript 或指定某厂商产品. 代码块标注实际语言.
- 代码保留完成当前任务需要的内容. 长行和长代码块确实妨碍理解时再拆分, 同一连续操作优先放在同一块里.
- 代码块前后说明它做什么, 在哪里执行和预期结果. 重复的说明删除, 注释只解释不明显的约束.
- 占位值要能识别出替换对象, 如 `your_access_token_here`. 保留配置格式要求的变量语法, 不改坏可执行内容.
- 不重复定义已给出的变量, 不堆无关默认值. 如果默认值影响理解或行为, 就明确写出.
- 指南在正文提供完成任务需要的示例, 不把关键步骤全部推到一个外部完整示例文件里.
- 对命令, API 签名, 模型标识和产品限制核对项目代码或官方资料. 使用与文档目标版本相符的内容, 不机械升级成最新版本.
- 能安全验证时实际检查示例, 如语法, 构建或隔离环境运行. 不为验证文档执行超出用户授权的部署, 删除或付费操作. 未执行的验证明确说明, 不声称示例已经运行.
- 链接使用准确的目的地和有含义的文字. 截图对应实际界面, 不把过期图片或虚构结果当作证据.
- 数据和单位表达清楚, 如 `64 KB`, `200 ms`. 同一文档沿用同一单位规则; 代码里的 `30s` 等合法语法保留.

# 从读者的起点检查

用文档声明的读者, 目标和初始条件走一遍主路径.  
检查读者能否仅靠本文及明确链接的前提材料完成目标, 查到参数或解释清楚原理. 如果不能, 补足阻碍任务的缺口.

| 检查项 | 要确认的问题 |
| --- | --- |
| 可找到 | 标题, 导航和链接能否把目标读者带到本页, 链接是否指向正确位置 |
| 准确 | 事实, 版本, 示例与界面是否吻合, 来源是否支持相关结论 |
| 相关 | 每个细节是否会改变理解或操作, 是否混入无关实现细节 |
| 清楚 | 主体, 动作, 条件和结果是否明确, 术语和指代是否可理解 |
| 足够 | 必要前提, 关键步骤, 限制, 例外和验证是否齐全 |
| 好读 | 句子是否顺畅, 段落是否聚焦, 标题能否预告内容, 强调是否有用 |

报告只包含当前范围内的问题, 按文件分组并定位. 优先报告会导致失败, 误解或错误决策的问题.  
用户要求审校时给问题和改法, 要求修改时直接完成修改. 不追加未经要求的发布, 联系他人或强制人工审批流程.
