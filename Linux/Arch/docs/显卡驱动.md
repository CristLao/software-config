<h1><center>显卡驱动 (Intel 核显 + NVIDIA 独显)</center></h1>

# 背景: 何时装什么驱动

显卡驱动在系统安装流程中的位置:

| 阶段 | 显卡状态 | 要做什么 |
|---|---|---|
| 系统安装 (1-基础安装.md) | 内核自带驱动 (i915 / nouveau / amdgpu) | 不装任何显卡包, 能亮机联网即可 |
| 桌面环境配置 (2-桌面环境.md) | "图形化相关包"一步 | 正式安装完整驱动 (本文档全部内容) |
| 内核例行更新 | DKMS 驱动已装 | 自动重新编译, 无需干预 |
| 更换内核 (3-性能优化.md) | 需新内核头文件 | 装对应 headers 后 DKMS 自动重编 |

要点:

- 系统安装阶段不要装显卡驱动, 内核自带驱动足够完成安装和首次进桌面
- 完整驱动在进入桌面环境配置阶段后, 统一在"图形化相关包"一步装齐, 装完重启
- 只要用 DKMS 版内核模块 (nvidia-580xx-dkms), 换内核/更新内核都会自动重编, 前提是装了对应版本的 linux-headers

本机方案实装于 2026-08-10 (联想 IdeaPad S540-14IWL).

# 方案选型

本机显卡: Intel UHD 620 (核显, WhiskeyLake) + NVIDIA MX150 (GP108M, Pascal 架构).

- 核显: 用 Mesa 开源栈 (官方仓库), 覆盖 OpenGL / Vulkan / OpenCL / VAAPI
- 独显: 用 AUR 闭源 580xx 分支 (580.173.02), 理由:
  - 官方仓库已无闭源 nvidia 内核模块, 只有 nvidia-open (610.43.03)
  - nvidia-open 仅支持 Turing (16系) 往后, MX150 是 Pascal (10系), 不支持
  - nouveau 无官方电源/时钟管理, 性能差且无硬解, 只适合应急亮机
  - NVIDIA 官方 5xx 分支是最后一个支持 Pascal 的闭源分支, AUR 有全套对应包
- 模式: PRIME 混合 (渲染卸载), 日常核显省电, 需要时 prime-run 调独显
- 备选: 若 580xx 出问题, 删除 mkinitcpio drop-in 即可回退 nouveau, 不会破坏系统

注: AUR 580xx 包近期被标记 OutOfDate (上游出了新版), 不影响使用, 580 分支仍支持 Pascal.

# 分层结构与所需包 (双显卡)

参考 2-桌面环境.md 的五层模型, 双显卡时每层装两张卡各自的包, 再加多卡联动包:

| 层 | Intel 核显 | NVIDIA 独显 | 双卡联动 |
|---|---|---|---|
| 1 物理硬件 | 显卡本体, 无包 | 显卡本体, 无包 | |
| 2 内核驱动 | 无 (i915 在内核, 固件在 linux-firmware) | nvidia-580xx-dkms + linux-headers | switcheroo-control |
| 3 用户态驱动 | mesa + lib32-mesa | nvidia-580xx-utils + lib32-nvidia-580xx-utils | |
| 4 图形 API | vulkan-intel + lib32-vulkan-intel | vulkan-icd-loader + lib32-vulkan-icd-loader (Vulkan 由 utils 自带) | vulkan-mesa-layers + lib32-vulkan-mesa-layers (vk-device-select) |
| 4 GPU 计算 | opencl-mesa (可换 intel-compute-runtime 提性能) | opencl-nvidia-580xx + lib32-opencl-nvidia-580xx | ocl-icd + lib32-ocl-icd (统一加载器) |
| 4 视频编解码 | intel-media-driver (iHD) | libva-nvidia-driver (桥接) | libva-utils (vainfo 验证) |
| 5 应用层 | | | gst-plugin-va + nvidia-prime (prime-run) |

# 安装步骤 (实装记录)

前提: 已装 paru (AUR 助手), 已进桌面环境配置阶段.

```bash
# 1. 内核头文件 (DKMS 编译需要, 版本须与内核一致)
sudo pacman -S --needed linux-headers

# 2. 独显驱动 (AUR 闭源 580xx): 内核模块 + 用户态 + 设置工具 + 32位库
paru -S --needed nvidia-580xx-dkms nvidia-580xx-utils nvidia-580xx-settings lib32-nvidia-580xx-utils

# 3. VAAPI 硬件编解码 (官方仓库, 桥接库)
sudo pacman -S --needed libva-nvidia-driver

# 4. OpenCL 运行时 (统一调用层 ocl-icd 已由 Mesa 栈装好)
paru -S --needed opencl-nvidia-580xx lib32-opencl-nvidia-580xx

# 5. PRIME 渲染卸载 + 切换服务
sudo pacman -S --needed nvidia-prime switcheroo-control
sudo systemctl enable --now switcheroo-control

# 6. 可选: vk-device-select (多显卡 Vulkan 选卡)
sudo pacman -S --needed vulkan-mesa-layers lib32-vulkan-mesa-layers

# 7. mkinitcpio: 加入 nvidia 模块并重建 initramfs
# 用 drop-in 配置 (与 chwd 同款, 不污染主配置), 卸载时删掉此文件即可回退
echo 'MODULES=(nvidia nvidia_modeset nvidia_uvm nvidia_drm)' | sudo tee /etc/mkinitcpio.conf.d/10-nvidia.conf
sudo mkinitcpio -P
```

装完重启生效. 核显侧包 (mesa, vulkan-intel, opencl-mesa, intel-media-driver, gst-plugin-va 等) 在"图形化相关包"整体安装时已包含, 无需重复.

# 使用

```bash
prime-run <程序>        # 用独显跑程序, 例: prime-run code
nvidia-settings         # 独显图形化控制面板
clinfo                  # 验证 OpenCL, 应看到 NVIDIA CUDA 平台
mpv --hwdec=vaapi 视频   # 视频硬解 (走 libva-nvidia-driver)
vainfo                  # 查看 VAAPI 支持, 双卡用 LIBVA_DRIVER_NAME 指定 (nvidia / iHD)
vulkaninfo --list-devices   # 查看两张卡的 Vulkan 设备
```

KDE 免命令方式: 开始菜单右键应用图标 -> 编辑应用程序 -> 命令前加 `prime-run `.

# 验证

```bash
nvidia-smi              # 识别 MX150, 驱动 580.173.02, 显存 2048MiB
lsmod | grep nvidia     # 应有 nvidia / nvidia_modeset / nvidia_uvm / nvidia_drm
lsmod | grep nouveau    # 应无输出 (已被屏蔽)
prime-run glxinfo | grep "OpenGL renderer"   # 应显示 NVIDIA GeForce MX150
```

# 故障处理

- 重启黑屏: 进 GRUB 高级选项选旧内核或急救 shell, 删除 drop-in 回退 nouveau:
  `rm /etc/mkinitcpio.conf.d/10-nvidia.conf && mkinitcpio -P`
- 内核更新后 nvidia 模块编译失败: 确认 linux-headers 版本与内核一致 (pacman -Q linux linux-headers)
- 更换内核 (如换 linux-zen): 装对应 headers, DKMS 自动重编, 重启后 lsmod 验证
- 独显过热/待机功耗异常: 见 3-性能优化.md (nvidia-powerd 动态功耗调节)

# 维护

- 更新驱动: `paru -Sua` 随系统更新 (AUR 包更新时 DKMS 自动重编)
- 完全卸载: `paru -Rns nvidia-580xx-* lib32-nvidia-580xx-* opencl-nvidia-580xx lib32-opencl-nvidia-580xx`, 并删 drop-in 重建 initramfs
- Wayland 下显卡切换不完善, 只能混合切核显, 独显直连需进 BIOS, 切换工具 (supergfxctl/envycontrol) 均已停更, 不用

# MX150 视频编解码最终结论

NVIDIA GeForce MX150 使用 Pascal GP108M 核心.  
NVIDIA 官方支持矩阵明确标注 MX150～MX330 的 NVENC 数量为 0, NVDEC 数量也为 0.  
这类显卡不具备 NVIDIA 硬件视频编码和解码单元.

实测现象与硬件限制一致:

- `nvidia-smi -q` 显示 Encoder, Decoder, JPEG, OFA 均为 `N/A`
- FFmpeg 使用 `h264_nvenc` 或 `hevc_nvenc` 报 `INVALID_ENCODERDEVICE`
- CUDA 计算和 PRIME 3D 渲染正常, 证明驱动和显卡本身没有故障
- Intel UHD 620 的 VAAPI 编解码正常, 视频编码和远程桌面应优先使用 Intel 核显

因此, 关闭 `NVreg_DynamicPowerManagement` 无法修复 NVENC/NVDEC.  
`INVALID_ENCODERDEVICE` 是硬件不支持的正常结果, 不是 Linux, 580xx 驱动或 DPM 导致的初始化失败.  
参考: [NVIDIA Video Encode and Decode Support Matrix](https://developer.nvidia.com/video-encode-decode-support-matrix).
