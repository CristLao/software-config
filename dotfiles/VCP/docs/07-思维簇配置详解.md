# 07 · 思维簇配置详解（VCP元思考）

> 位置：`VCPToolBox/dailynote/<簇名>/` + `VCPToolBox/Plugin/RAGDiaryPlugin/meta_thinking_chains.json`  
> 机制：VCP 元思考（递归推理链）通过多阶段向量召回，让 AI 从"信息检索"进化为"结构化思考"  
> 官方指南：`VCPToolBox/Plugin/RAGDiaryPlugin/META_THINKING_GUIDE.md`

---

## 1. 思维簇是什么

思维簇（Thought Cluster）是 **元逻辑模块** 的集合。每个模块是一个独立的思考单元（触发条件 / 核心功能 / 执行流程），AI 在回答前会按"链"的顺序逐簇召回模块，前一阶段的结果参与下一阶段的向量融合，形成思考递进。

```
用户输入 → 向量化 →
  ↓
阶段1: 前思维簇 (k=2) → 召回2个元逻辑 → 向量融合(40%上下文 + 60%结果)
  ↓
阶段2: 逻辑推理簇 (k=1) → 召回1个元逻辑 → 向量融合
  ↓
阶段3: 反思簇 (k=1) → 召回1个元逻辑 → 向量融合
  ↓
阶段4: 结果辩证簇 (k=1) → 召回1个元逻辑 → 向量融合
  ↓
阶段5: 陈词总结梳理簇 (k=1) → 召回1个元逻辑 → 完整思维链
```

---

## 2. 架构：两层配置

| 层 | 位置 | 作用 |
|---|---|---|
| **簇内容** | `dailynote/<簇名>/` 下的 `.md` 文件 | 元逻辑模块（每个文件一个【思考模块】） |
| **链配置** | `Plugin/RAGDiaryPlugin/meta_thinking_chains.json` | 链(chain) → 簇列表 + K值序列 的映射 |

消费方：

- `MetaThinkingManager.js`：元思考递归推理引擎（加载链配置执行多阶段召回）
- `ThoughtClusterManager` 插件：思维簇管理工具（ListClusters / CreateClusterFile / EditClusterFile）
- `PlaceholderExplorer`：解析 `[[VCP元思考:...]]` 占位符

---

## 3. 簇内容：元逻辑模块格式

每个簇文件夹（如 `前思维簇/`）下放多个 `.md` 文件，每个文件是一个独立完整的思考单元：

```markdown
【思考模块：模块名】
【触发条件】：什么场景下启用该模块。
【核心功能】：
1. 功能一
2. 功能二
【执行流程】：
1. 步骤一
2. 步骤二
```

要点：

- 文件名建议时间戳（如 `2026-03-15T03-50-09-922Z.md`），插件自动生成
- 模块须独立完整、可单独理解，避免依赖其他模块上下文
- 长度建议 200-500 字，可直接被向量召回命中
- 簇文件夹名**必须以"簇"结尾**（插件硬性校验）

## 4. 链配置：meta_thinking_chains.json

新版实际格式（注意：官方指南中的数组格式是旧版，新版为 `clusters + kSequence` 对象结构）：

```json
{
  "chains": {
    "default": {
      "clusters": ["前思维簇", "逻辑推理簇", "反思簇", "结果辩证簇", "陈词总结梳理簇"],
      "kSequence": [2, 1, 1, 1, 1]
    }
  },
  "description": "VCP元思考链配置文件 - 定义递归推理链的簇顺序",
  "version": "1.0.0"
}
```

| 字段 | 说明 |
|---|---|
| `chains.<名称>` | 链名（占位符引用时使用），任意字符串 |
| `clusters` | 该链依次执行的簇文件夹名数组（须与 dailynote 目录一致） |
| `kSequence` | 每个簇的召回数量，长度必须与 clusters 一致 |

> ⚠️ 修改后需重启生效：`pitchfork restart vcp-main`

## 5. 配置步骤（从零新增一条链）

```
1. 创建簇文件夹 + 模块文件
   dailynote/我的新簇/
   └── 2026-03-15T03-50-09-922Z.md   # 按【思考模块】格式编写

2. 定义链（编辑 meta_thinking_chains.json）
   在 chains 下追加：
   "mychain": {
     "clusters": ["我的新簇", "反思簇"],
     "kSequence": [2, 1]
   }

3. 重启生效
   pitchfork restart vcp-main

4. 验证
   echo '{"command":"ListClusters","chainName":"mychain"}' \
     | node Plugin/ThoughtClusterManager/ThoughtClusterManager.js
```

## 6. 使用方式（占位符语法）

```
[[VCP元思考:<链名称>::<修饰符>:<k1-k2-k3-...>]]
```

| 部分 | 说明 |
|---|---|
| 链名称 | 可选，默认 `default` |
| 修饰符 | 可选，`::Group` 启用语义组增强 |
| K值序列 | 必需，数量须与链的簇数一致 |

示例：

```
[[VCP元思考::Group:2-1-1-1-1]]        # 默认链 + 语义组
[[VCP元思考:zhongyi::Group:1-2-2-1-3-1-1]]  # 中医链
[[VCP元思考:investment::Group:1-2-2-1-1]]   # 投资链
[[VCP元思考:dev::Group:1-1-2-2-3-1]]        # 开发链
```

K值设计原则：**前期宽度，后期收敛**（如 `2-2-1-1-1`）；简单问题用 `1-1-1-1-1`。

## 7. 管理工具：ThoughtClusterManager 插件

三个命令（stdin JSON 调用）：

| 命令 | 用途 | 关键参数 |
|---|---|---|
| `ListClusters` | 查看簇内容 | `clusterName`（指定簇）/ `chainName`（按链查）/ 空（全量枚举） |
| `CreateClusterFile` | 新建簇 + 写入模块 | `clusterName`（须以"簇"结尾）/ `content` |
| `EditClusterFile` | 查找替换模块内容 | `clusterName`（可选）/ `targetText`（≥15字）/ `replacementText` |

批量调用用 `command1/command2...` + `clusterName1/content1...` 串行参数。

```
1. 迁移簇内容（dailynote 文件夹）
   前提：新版已存在的文件夹不迁移（不覆盖）
   for d in 旧版dailynote/*/; do

     [ -d "新版dailynote/$name" ] || cp -a "$d" "新版dailynote/$name"

2. 迁移链配置（meta_thinking_chains.json 合并）
   # 备份新版 → node 脚本合并旧版缺失的链 → 写回 → JSON 校验

   echo '{"command":"ListClusters","chainName":"investment"}' \

```

- 验证：JSON 校验通过，插件按链名可正确解析全部簇内容
- 兼容性：新版 `placeholder-index.json` 中 `[[VCP元思考:zhongyi::Group]]` 占位符在迁移后可正常解析

## 10. 故障排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 提示"未找到元逻辑模块" | 簇文件夹不存在或为空 | 检查 `dailynote/` 下簇文件夹及 `.md` 文件 |
| 思维链执行缓慢 | K 值过大 | 降低 K 值序列（如 `2-1-1-1-1`） |
| 推理结果不理想 | 模块质量差或向量未重建 | 优化模块内容；删除向量缓存让系统重建索引 |
| 链解析失败"未找到链" | 链名不存在 | 检查 `meta_thinking_chains.json` 链名拼写 |
| 改配置不生效 | 未重启 | `pitchfork restart vcp-main` |
