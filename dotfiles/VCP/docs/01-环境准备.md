# 01 · 环境准备（工具链）

> 目标：装好 mise、Node 22、uv、pitchfork，并验证版本。

---

## 1. 安装 mise

mise 是版本管理器（类似 nvm+pyenv+asdf 合一），本项目用它锁定 node/uv 版本, pitchfork 走全局安装。

**Arch Linux：**

```bash
sudo pacman -S mise
```

**其他发行版 / macOS：**

```bash
curl https://mise.run | sh
# 或
brew install mise
```

**激活 mise**（写入 shell 配置，如 `~/.bashrc`）：

```bash
echo 'eval "$(mise activate bash)"' >> ~/.bashrc
source ~/.bashrc
```

---

## 2. 项目工具版本（mise.toml）

在 VCP 根目录创建 `mise.toml`（本目录已附一份，直接复制）：

```toml
# VCP 项目工具版本管理
# 虚拟环境由 uv 管理, mise 仅负责进入目录时自动激活 .venv
[env]
PROJECT_NAME = "{{ config_root | basename }}"
_.python.venv = { path = ".venv", create = false } # 仅激活, 不创建

# 项目工具 (进入目录时由 mise 自动安装/激活)
[tools]
node   = "22.23.2"
uv     = "latest"
```

> **Node 版本说明**：锁定 **22.x LTS**（22.23.2）。  
> 原因：VCPToolBox 依赖 better-sqlite3 原生模块，Node 24 的 ABI（NODE_MODULE_VERSION 137）会触发 better-sqlite3 原生崩溃（`Assertion failed: env != nullptr`）。Node 22 的 ABI（127）完全稳定。

**pitchfork（进程管理器, 全局安装一次即可）：**

```bash
mise use -g pitchfork    # 写入全局 mise 配置, 所有目录可用
```

**进入目录自动安装并激活：**

```bash
cd VCP
mise install          # 按 mise.toml 安装 node 22.23.2 + uv
mise use node@22.23.2 # 确认锁定
```

**验证：**

```bash
node --version                 # v22.23.2
node -e "console.log(process.versions.modules)"  # 127
uv --version                   # 0.12.x
pitchfork --version            # 2.x
```

> ⚠️ 每次新开终端进入 VCP 目录，mise 会自动激活正确版本。  
> 若在脚本/子 shell 中需要手动激活：`eval "$(mise activate bash)"`

## 3. 上游 API 网关（前置依赖）

VCP 本身不直接调用模型厂商，需要一个 **OpenAI 兼容网关**（如 NewAPI）提供：

- **聊天模型**：如 `qwen3.6-plus`、`gemini-2.5-pro` 等
- **向量模型**：如 `gemini-embedding-2-preview`（知识库向量化必需）

网关地址记为 `API_URL`（默认 `http://localhost:3000`），密钥记为 `API_Key`。

> ⚠️ 安全提示：请使用官方或可信聚合 API。VCP Agent 拥有分布式系统级权限，使用不可信反代可能导致数据泄露。

---

## 4. Python 虚拟环境（uv）

VCPToolBox 的 Python 依赖（科学计算、图像处理）由 uv 管理：

```bash
cd VCP
uv venv .venv          # 创建虚拟环境
source .venv/bin/activate
python --version       # 3.13.x（本项目验证于 3.13.2）
```

> mise.toml 配置了 `_.python.venv = { path = ".venv", create = false }`，进入目录时 mise 自动激活 .venv，无需手动 source。
