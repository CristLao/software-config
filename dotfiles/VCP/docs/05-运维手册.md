## 1. Pitchfork 常用操作

```bash
# 状态
pitchfork list                 # 列表（vcp-main / vcp-admin）, 别名 ls
pitchfork status vcp-main      # 单个详情（pid / status）
pitchfork list --json          # JSON 详情（机器可读）

# 日志（存于 SQLite, 经命令读取, 无 ~/.pm2/logs 文本文件）
pitchfork logs vcp-main -t                  # 实时跟随
pitchfork logs vcp-main -n 100              # 最近 100 行
pitchfork logs vcp-main --level error -n 50 # 错误日志
pitchfork logs vcp-main --raw -n 100        # 纯文本输出, 适合管道/grep

# 生命周期
pitchfork start vcp-main            # 启动（幂等: 已运行则跳过）
pitchfork restart vcp-main          # 重启（配置修改后）
pitchfork restart vcp-main vcp-admin
pitchfork stop vcp-main             # 停止（别名 kill）
pitchfork clean --daemon vcp-main   # 清理停止/失败的残留记录
pitchfork supervisor stop           # 重启 Supervisor（换 node 版本后建议做）
pitchfork boot enable               # 开机自启（生成 systemd 单元, daemon 需配 boot_start = true）
```

> ⚠️ **pitchfork start 是幂等的**: 已运行的 daemon 直接跳过, 不像 pm2 每次都重启。
> 配置修改后用 `pitchfork restart`, 或 `pitchfork start --force`。
>
> ⚠️ **切换 Node 版本后**: 执行 `pitchfork supervisor stop`, 下次命令会自动以新环境拉起 Supervisor。
> daemon 已配置 `mise = true`, 运行时经 `mise x` 按项目 mise.toml 解析 node 版本, 一般无需额外处理。

## 2. 备份与恢复

### 2.1 数据库备份

VCPToolBox 根目录提供备份脚本：

```bash
# 备份（默认输出 backup.sql）
python3 backup_vcp.py

# 恢复
./restore-db.sh backup.sql
```

备份内容：知识库 SQLite（TagMemo 索引、向量）、配置。

### 2.2 数据目录备份（建议 cron 每日）

```bash
# 后端
tar czf vcp-backup-$(date +%F).tar.gz \
  VCPToolBox/config.env \
  VCPToolBox/agent_map.json \
  VCPToolBox/multimodal-config.json \
  VCPToolBox/dailynote \
  VCPToolBox/knowledge \
  VCPToolBox/VectorStore

# 客户端
tar czf vcpchat-data-$(date +%F).tar.gz VCPChat/AppData
```

## 5. 故障排查手册

### 5.1 原生崩溃（Assertion failed）

```
Assertion failed: (env) != nullptr
Statement::~Statement() better_sqlite3
```

- **原因**：Node 版本过新（24+）与 better-sqlite3 ABI 不兼容
- **解决**：切回 Node 22（见 01-环境准备），然后：
  ```bash
  pitchfork supervisor stop
  eval "$(mise activate bash)"
  cd VCPToolBox && npm rebuild better-sqlite3
  pitchfork restart vcp-main vcp-admin
  ```

### 5.2 better-sqlite3 bindings 缺失

```
Could not locate the bindings file
```

```bash
npm approve-scripts better-sqlite3
npm rebuild better-sqlite3
node -e "require('better-sqlite3'); console.log('OK')"
```

### 5.3 知识库向量化失败

```
[Embedding] Model "xxx" failed: API Error 503 model_not_found
```

- 模型名与网关渠道名不一致（勿加 `google/` 等前缀）
- 改 `config.env` 的 `WhitelistEmbeddingModel` / `EmbeddingModelBackup*` 后重启

```
[Embedding] ... 模型不匹配向量化模型白名单
```

- 灾备模型未加入 `WhitelistEmbeddingModel` 白名单（`/v1/embeddings` 路由白名单校验）
- 将全部灾备模型名以逗号分隔写入 `WhitelistEmbeddingModel` 后重启

```
[Embedding] ... 上游负载已饱和 / upstream error
```

- 单个灾备渠道暂时性故障，灾备链会自动跳过切下一个
- 持续失败需在 new-api 面板检查该渠道 key/状态

**排查命令**：逐个测试灾备模型可用性

```bash
for m in gemini-embedding-2-preview{1..5}; do
  curl -s -m 30 http://localhost:6005/v1/embeddings \
    -H "Authorization: Bearer <Key>" -H "Content-Type: application/json" \
    -d "{\"model\":\"$m\",\"input\":[\"测试\"]}" | head -c 80
  echo " <- $m"
done
```

### 5.4 服务反复重启（retry 持续触发）

1. 看错误日志定位：`pitchfork logs vcp-main --level error -n 50`
2. 常见原因：原生模块 ABI 不匹配、端口占用、配置错误
3. 检查是否有旧实例占端口：`ss -tlnp | grep 6005`，`pkill -f "server.js"`
4. pitchfork 的 `retry = true` 会无限重试崩溃进程，修复根因后 `pitchfork restart vcp-main` 归位

### 5.5 VCPChat 音频引擎问题

| 症状 | 处理 |
|---|---|
| `spawn audio_server EACCES` | `chmod +x audio_engine/audio_server` |
| `Address already in use` | `pkill -f audio_server` |
| 无声/引擎未启动 | 检查 `audio_engine/.env`，验证 `./audio_engine/audio_server --help` |

### 5.6 VCPChat 窗口不显示（Linux Wayland）

```bash
npx electron . --no-sandbox --ozone-platform=x11
```

### 5.7 VCP-CDS 冲突

```
another VCP-CDS instance already owns AppData
```

```bash
pkill -f vcp_chat_data_service   # 清理孤儿实例
pkill -f electron                # 必要时全清
```

### 5.8 管理面板打不开

- 确认 `vcp-admin` running：`pitchfork list`
- 确认 AdminPanel-Vue 已构建：`ls VCPToolBox/AdminPanel-Vue/dist/index.html`
- 未构建则：`cd AdminPanel-Vue && npm install && npm run build`

## 6. 性能调优

| 参数 | 位置 | 建议 |
|---|---|---|
| `UV_THREADPOOL_SIZE=64` | pitchfork.toml 的 env（已配置） | 大知识库必需，CPU 紧张可降 32 |
| `KNOWLEDGEBASE_EVENT_LOOP_WATCHDOG_MS` | config.env | 5000（默认），阻塞告警 |
| TagMemo EPA 重算 | `KNOWLEDGEBASE_EPA_BACKGROUND_RECOMPUTE` | 首次启动建议 false，稳定后开 |
| `memory_limit` | pitchfork.toml | **不要设置**（冷启动内存尖峰会误杀） |

## 7. 一键脚本参考

`start-all-mise.sh`（与本文档同目录）已封装完整流程：

```bash
./start-all-mise.sh            # 环境→依赖→构建→启动（含 VCPChat）
./start-all-mise.sh --no-chat  # 仅后端
./start-all-mise.sh --desktop  # 后端 + VCPChat 桌面模式
```

脚本内容要点（便于自维护）：

1. `mise activate` → 保证 node 22 / uv / pitchfork
2. uv 建 `.venv` + 装 Python 依赖（Linux 排 win10toast）
3. 检查 config.env / node_modules / AdminPanel dist，缺失则补齐
4. new-api 探测（存在 start-newapi.sh 才启动，可选）
5. `pitchfork start vcp-main vcp-admin`（幂等, 就绪检查通过才返回; UV_THREADPOOL_SIZE 已写入 pitchfork.toml 的 env）
6. 可选启动 VCPChat
