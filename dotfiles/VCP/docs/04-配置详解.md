## 3. 向量模型（知识库核心）

| 配置项 | 说明 |
|---|---|
| `WhitelistEmbeddingModel` | 主向量模型 + 白名单（**逗号分隔，灾备模型也必须列入**） |
| `EmbeddingModelSig` | 向量模型签名（用于索引缓存识别） |
| `EmbeddingModelBackup1..9` | 备援模型链（失败自动切换） |
| `WhitelistEmbeddingModelMaxToken` | 单文本最大 token（8000） |
| `WhitelistEmbeddingModelList` | 并发批次数（5） |

**推荐配置（gemini-embedding-2-preview 多渠道灾备链）：**

```bash
# ⚠️ 白名单必须包含主模型 + 全部灾备模型（逗号分隔）
WhitelistEmbeddingModel=gemini-embedding-2-preview,gemini-embedding-2-preview1,gemini-embedding-2-preview2,gemini-embedding-2-preview3,gemini-embedding-2-preview4,gemini-embedding-2-preview5
EmbeddingModelSig=gemini-embedding-2-preview

# 灾备链：主模型失败后按编号依次切换
EmbeddingModelBackup1=gemini-embedding-2-preview1
EmbeddingModelBackup2=gemini-embedding-2-preview2
EmbeddingModelBackup3=gemini-embedding-2-preview3
EmbeddingModelBackup4=gemini-embedding-2-preview4
EmbeddingModelBackup5=gemini-embedding-2-preview5
```

> 踩坑：写成 `google/gemini-embedding-2-preview` 等带厂商前缀 → 网关报 `model_not_found`，知识库向量化全挂。

### 3.1 灾备机制详解

**架构**：VCP → new-api 网关 → 多上游渠道（aihubmix/orcarouter/linkapi/n1n/xiaocaseai）

- VCP 只请求网关，**不直连**上游厂商
- 每个灾备模型名（`gemini-embedding-2-preview1..5`）由 new-api 路由到独立渠道
- `EmbeddingModelBackup*` 只切换**模型名**，URL/Key 始终用主网关（`API_URL`/`API_Key`）
- 主模型失败（超时/500/503/429）→ 按编号尝试 `Backup1` → `Backup2` → …

**⚠️ 关键坑：白名单同步**

`/v1/embeddings` 网关路由有白名单校验（`routes/specialModelRouter.js`）：

```js
if (!WHITELIST_EMBEDDING_MODELS.includes(model)) {
    return res.status(400).json({ error: "模型不匹配向量化模型白名单" });
}
```

- 白名单只从 `WhitelistEmbeddingModel` 读取（逗号分隔）
- **`EmbeddingModelBackup*` 不会自动加入白名单** → 灾备模型必须显式写进 `WhitelistEmbeddingModel`
- 漏配的症状：灾备请求被 400 拦截，日志报 `模型不匹配向量化模型白名单`

**渠道对照表**（模型名 → new-api 渠道，需在网关侧配置）：

| VCP 模型名 | 渠道 | 上游 |
|---|---|---|
| `gemini-embedding-2-preview` | 聚合/默认 | new-api 默认路由 |
| `gemini-embedding-2-preview1` | xiaocaseai | api.xiaocaseai.com |
| `gemini-embedding-2-preview2` | linkapi | hk.linkapi.ai |
| `gemini-embedding-2-preview3` | n1n | api.n1n.ai |
| `gemini-embedding-2-preview4` | orcarouter | api.orcarouter.ai |
| `gemini-embedding-2-preview5` | aihubmix | aihubmix.com |

**验证灾备链**：

```bash
# 逐个测试各模型（应返回 3072 维向量）
for m in gemini-embedding-2-preview{1..5}; do
  curl -s -m 30 http://localhost:6005/v1/embeddings \
    -H "Authorization: Bearer <Key>" -H "Content-Type: application/json" \
    -d "{\"model\":\"$m\",\"input\":[\"测试\"]}" | head -c 80
  echo " <- $m"
done
```

> 注意：某渠道返回 `上游负载已饱和` / `upstream error` 是暂时性故障，灾备链会自动跳过；若持续失败需在 new-api 面板检查该渠道 key/状态。
